  extended_description: |
    ## cbor — CBOR (RFC 8949) + MessagePack in SQL

    Decode, validate, canonicalize, tag-project, and transcode binary
    self-describing data right where you query it — with first-class COSE
    payload / thumbprint extraction for JWS/CWT/WebAuthn workflows.
    The lossless JSON projection for CBOR, EDN for the debug view.

    The engine (`cbor_core/`) is a verbatim port of the
    [Query-farm `vgi-cbor`](https://github.com/Query-farm/vgi-cbor)
    cbor-core crate (MIT/Apache-2.0) — a pure-Rust structural decoder with
    no Arrow, no VGI, and no cryptographic verification; only the transport
    layer was replaced with direct DuckDB C-API vector I/O (via
    [quack-rs](https://github.com/tomtom215/quack-rs)).

    **11 Functions:**

    | Function | Signature | Returns |
    |----------|-----------|---------|
    | `cbor_to_json` | `(blob)` | `VARCHAR` — canonical JSON (byte strings as base64url) |
    | `cbor_diagnostic` | `(blob)` | `VARCHAR` — RFC 8949 §8 Extended Diagnostic Notation |
    | `cbor_is_valid` | `(blob)` | `BOOLEAN` — exactly one well-formed item, no trailing bytes |
    | `cbor_well_formed` | `(blob)` | `STRUCT(ok, error, kind)` — classified failure taxonomy |
    | `cbor_untag` | `(blob, tag UBIGINT)` | `VARCHAR` — JSON array of values under a semantic tag |
    | `cbor_from_json` | `(json VARCHAR)` | `BLOB` — JSON text -> core-deterministic CBOR |
    | `cbor_canonical` | `(blob, mode VARCHAR)` | `BLOB` — deterministic re-encode (`core` / `ctap2`) |
    | `cbor_cose_payload` | `(blob)` | `BLOB` — COSE inner payload (tagged or unprotected) |
    | `cbor_cose_x5t` | `(blob)` | `VARCHAR` — COSE x5t thumbprint (lowercase hex) |
    | `msgpack_to_json` | `(blob)` | `VARCHAR` — MessagePack -> JSON (ext/timestamp handled) |
    | `msgpack_to_cbor` | `(blob)` | `BLOB` — MessagePack -> CBOR transcode |

    Decoders are total and bound recursion at a fixed max nesting depth, so
    a hostile blob fails its own row, never crashes the scan. NULL flows
    through; malformed input -> NULL (except `cbor_canonical` with an
    unknown `mode`, which is a caller mistake -> clean SQL error).
