    Next-generation build of the [`qvd`](https://github.com/duckdb/community-extensions/tree/main/extensions/qvd)
    extension, on DuckDB's C API v2 (via the `duckdb-neo` crate). Same SQL surface
    (`read_qvd`, `COPY ... (FORMAT qvd)`), plus:

    - `COPY ... TO` keeps the query's column names (`FIELD_NAMES` becomes an
      optional override);
    - `COPY ... FROM` casts values to the target table's column types;
    - `read_qvd(path)` is documented in `duckdb_functions()`.

    Reading is streaming and projected (bounded memory; only the projected
    columns' symbol tables are read and decoded), with native typing from the
    Qlik tags, projection pushdown and multi-file glob. All I/O goes through
    DuckDB's file system, so `s3://`, `https://`, etc. work once httpfs is
    loaded (remote globs included). QVD headers are validated against the file
    before reading, so corrupt files fail cleanly.

    Trade-off: the C API v2 is not stable yet, so this build targets one exact
    DuckDB version and is experimental. `qvd` (stable C ABI) remains the
    conservative choice. Load only one of `qvd` / `qvd_next` per session: both
    register `read_qvd` and `FORMAT qvd`.
