  extended_description: |
    `dc` brings a two-stage AI enrichment pipeline into DuckDB SQL.

    **System One** handles bounded, highly batchable judgments with
    `system_one_choice`, `system_one_score`, `system_one_noul`, and the
    relation-oriented `system_one_stream`. Semantic Resolution assigns foreign
    keys from per-row candidates with `system_one_resolve` and
    `system_one_resolve_stream`, including explicit `matched`, `ambiguous`, and
    `no_match` outcomes. **System Two** handles generation, summarization, and
    structured extraction with `system_two_generate`, `system_two_summarize`,
    and `system_two_extract`.

    The two paths compose through ordinary SQL. A query can classify every row
    with System One, escalate only results below a confidence threshold to
    System Two, and retain a single final column alongside the candidate,
    confidence, threshold, escalation result, and selected source.

    The native extension deduplicates equivalent work, batches rows, bounds
    concurrent provider requests, validates responses, stops queued work and
    aborts active client transfers when DuckDB interrupts a query, and offers
    query-local coalescing plus optional per-connection TTL/LRU caches.
    `dc_stats()` reports request, item, cache, retry, error, token, byte, and
    latency metrics independently for both systems.

    Provider credentials are stored through DuckDB's Secret Manager and are
    redacted from `duckdb_secrets()`. Plain HTTP endpoints are rejected except
    for loopback testing, and `SET enable_external_access = false` disables
    provider calls.

    Full SQL reference and runnable examples:
    https://github.com/prasanthj/duckdb-dual-cognition
