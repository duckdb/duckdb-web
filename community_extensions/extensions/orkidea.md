  extended_description: |
    Orkidea makes an Oracle schema behave like a DuckDB database you can
    change, not just read: `INSERT`, `CREATE TABLE ... AS`, `UPDATE`,
    `DELETE`, `RETURNING`, `ON CONFLICT`, `INSERT OR REPLACE`, `MERGE INTO`,
    `CREATE`/`DROP TABLE`, and `ALTER TABLE` (add, drop, and rename columns,
    change types, defaults, `NOT NULL`, primary keys), all inside DuckDB
    transactions that commit or roll back on Oracle. Defaults and identity
    columns are left to Oracle, and `RETURNING` gives the rows as Oracle
    stored them.

    It is built on the [Orkidea ADBC driver](https://github.com/Tnsor-Labs/orkidea-adbc),
    a standalone Rust implementation of Oracle's network protocol that is
    linked into the extension, so there is no Instant Client, OCI, or ODBC to
    install. Results stream into DuckDB as Arrow record batches with exact
    types (`NUMBER(p,s)` as `DECIMAL`, `TIMESTAMP WITH TIME ZONE` as
    `TIMESTAMPTZ`, LOBs, intervals, `JSON`, and `VECTOR`).

    - **Secrets**: host/port/service, connect strings, `tnsnames.ora`
      aliases, wallets, and TLS.
    - **ATTACH**: filters, projections, `LIMIT`, and top-N queries are pushed
      down to Oracle.
    - **Parallel scans**: large tables are read by several sessions over
      ROWID ranges at one SCN, so the result is a consistent snapshot.
    - **Federation**: join Oracle with Postgres, Parquet, or any other source
      DuckDB reads.
    - `orkidea_query` and `orkidea_execute` run Oracle SQL and PL/SQL.

    Not affiliated with, sponsored by, or endorsed by Oracle Corporation.
