  extended_description: |
    `tidbfs` is a native C++ filesystem extension for TiDB Filesystem. It calls
    the existing HTTP data plane directly, without FUSE or a Go runtime.
    Its initial community release targets DuckDB 2.0.0 on Linux amd64 (glibc)
    and macOS arm64. OpenSSL and libcurl are statically linked into the artifact.

    The `tidbfs:///` scheme supports Parquet, CSV and JSON reads, globbing,
    Hive partition pruning, `COPY TO`, partitioned output, and database
    `EXPORT`/`IMPORT`. Reads use conditional HTTP Range requests and parallel
    reads. Writes stage locally and publish a complete file using the server's
    revision checks and multipart upload APIs. They require local scratch
    space; multi-file operations are not atomic transactions.

    Experimental `tidbfs+db:///` storage can place native DuckDB database and
    WAL files on the same filesystem using the public extent API and C++ SDK.
    It preserves the existing sessions, advisory file locks and persistence
    contract. All writers must cooperate with these locks; this is not a
    replacement for DuckDB's concurrency rules or a claim of arbitrary
    multi-process writer support. Native mode requires an unscoped filesystem
    token and a server with the documented extent/session APIs.

    See the [compatibility matrix](https://github.com/drive9-ai/duckdb/blob/main/docs/compatibility.md)
