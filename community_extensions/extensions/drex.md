  extended_description: |
    `drex` connects DuckDB to Drex, Nace's decision models, to classify text, score rows and return
    probabilities as native SQL values. `prompt_drex` asks a typed question about each row:

    - **Yes/no** (`noul`, the default) returns a `DOUBLE`, the probability that the answer is true.
    - **One label of a set** (`choice := [...]`) returns a `STRUCT` with the label, every label's probability
      and a confidence.
    - **A score on ordered levels** (`score := [...]`) returns a `STRUCT` with the score, every level's
      probability and a confidence.
    - **Several questions at once** (`questions := {...}`) asks up to 512 in one request per row and returns
      one struct field per question.

    The arguments and result types follow MotherDuck's `prompt_jev`, plus `model :=` (the default is
    `drex-v2.0`). Inputs can be `VARCHAR`, `JSON`, or a `BLOB` or `BLOB[]` of PNG, JPEG or WebP images on an
    image-capable model such as `drex-max`. `drex_decide` sends JSON state and questions and returns the
    API's answer as JSON.

    **Credentials.** `CREATE SECRET (TYPE nace, PROVIDER env)` reads `NACE_API_KEY` (and an optional
    `NACE_BASE_URL`) from the environment, which keeps the key out of SQL history.

    **Requests.** Each evaluated non-NULL row normally makes one request. Requests run concurrently
    (`drex_max_concurrency`, 8 by default, or `concurrency := N` per call), with an optional requests-per-minute
    cap (`drex_max_rpm`). Transient failures and rate limits are retried within a bounded budget, honoring
    the server's retry headers. A row the API refuses (an oversized input, an invalid image) returns NULL
    with a warning; authentication, billing and unknown models fail the query.

    - SQL API reference: https://github.com/nace-ai/drex-duckdb/blob/v0.1.0/docs/API.md
    - Issues: https://github.com/nace-ai/drex-duckdb/issues
