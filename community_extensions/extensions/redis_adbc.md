    This submission targets DuckDB 2.0 through the registry's repo.ref field.

    `redis_adbc_scan(uri, sql)` streams one SELECT from Redis into DuckDB using
    the Redis ADBC driver's SQL engine and Arrow batches. The driver and Go
    runtime are embedded: no separate driver library, manifest, driver manager,
    or adbc_scanner installation is required.

    Redis Search is required. Use `rediss://` for TLS. SQL over driver-managed
    tables can use Search predicate and aggregate pushdown; surrounding DuckDB
    queries can join and aggregate the streamed results locally. Existing HASH
    collections need the driver's copy/adoption workflow to become SQL tables.

    This is a read interface: scripts, DDL, DML and transaction commands are
    rejected. It does not provide ATTACH catalogs, ingestion, or query parameter
    binding. For those integration APIs, use the Redis driver through the
    existing adbc_scanner extension. This extension is distinct from the
    separately registered redis command-client extension.

    Native Linux and macOS are supported build targets; macOS requires 12+.
    See the [extension guide](https://github.com/alberttwong/redis-adbc-driver/blob/8f4c5f5763dbef7fa4f096b6da2d19218e6fb9d3/duckdb-extension/README.md)
    for build instructions, prerequisites, limitations and verification.
