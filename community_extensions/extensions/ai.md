  extended_description: |
    The `ai` extension brings language models into DuckDB SQL. Point a function at a column and it calls
    the model once per row, several rows at a time, and returns an ordinary DuckDB value (`VARCHAR`,
    `BOOLEAN`, `DOUBLE`, a typed `STRUCT`, a `LIST` or an embedding) that you can filter, join, aggregate
    and save like any other column.

    **What you can do**

    - Label and rewrite text: `ai_classify`, `ai_classify_labels`, `ai_sentiment`, `ai_summarize`,
      `ai_translate`, `ai_fix_grammar`, `ai_redact`, `ai_complete`.
    - Get typed answers instead of free text: `ai_extract_record` returns a `STRUCT` from a JSON Schema
      (pydantic schemas work), `ai_filter` a `BOOLEAN`, `ai_score` a `DOUBLE` from 0 to 1, and
      `ai_complete_json` validated JSON.
    - Ask several typed questions per row with decision models: `ai_decide` returns probabilities and
      confidences from TypeSafe Jev, Cloudflare Clef, Perplexity or a local decision model.
    - Search by meaning: `ai_embed`, `ai_similarity` and `ai_rerank`, with `ai_generate_chunks` and
      `ai_prep_search` to split long documents.
    - Summarize groups with the `ai_agg` and `ai_summarize_agg` aggregates.
    - Ask questions about your data: `ai_sql` writes a validated read-only `SELECT` from your schema, and
      `ai_query_data` runs it.

    **Any model, local or hosted**

    Local model servers keep data on your machine: Ollama, llama.cpp, LM Studio, vLLM or any
    OpenAI-compatible endpoint. Hosted APIs include OpenAI, Anthropic, Google Gemini and Vertex AI, Azure
    OpenAI, Amazon Bedrock, Mistral, DeepSeek, Groq, Together, OpenRouter, Databricks and Snowflake Cortex,
    among more than 35 providers. Switching is one setting; the SQL stays the same. Replies are read the way
    small models write them, so a label in markdown or followed by an explanation still counts.

    **Safe to run on real tables**

    - API keys come only from environment variables or `TYPE duckdb_ai` secrets, never from SQL arguments.
      Loading the extension makes no network calls, and `allowed_hosts` limits where data can be sent.
    - `ai_completion_request_json` shows a request without sending it. `ai_usage()` and
      `ai_usage_summary()` track calls, tokens, failures and estimated cost.
    - Per-row error handling (`on_error := 'null'`, `ai_try_complete`), retries with backoff, rate and
      concurrency limits, and an opt-in response cache keep long batch runs predictable.

    **Learn more**

    - Documentation: https://leonardovida.github.io/duckdb-ai/docs
    - Function reference: https://leonardovida.github.io/duckdb-ai/docs/functions
    - Cookbooks for ticket triage, semantic search, resumable batch runs and cost tracking:
      https://leonardovida.github.io/duckdb-ai/docs/cookbooks
