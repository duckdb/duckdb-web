  extended_description: |
    capped gives DuckDB tables that forget. You set a limit on each table when
    you create it: how old rows may get (`ttl`), how big the table may grow
    (`max_bytes`), or how many rows it may hold (`max_rows`). New rows keep
    coming in, and the oldest data is removed whenever a limit is passed.

    It is built for telemetry such as logs, traces, metrics and events, where
    nobody needs last month's data and nobody wants to schedule cleanup jobs.

    Each table is stored as a series of immutable Parquet files. Removing old
    data means deleting whole files, so nothing is rewritten, no space is
    left behind, and size limits are exact. Queries go through DuckDB's own
    Parquet reader, so filters and pushdown work as usual.

    Retention runs when a store is attached, on every write, and on a
    background thread. Tables can also opt in to full-text and vector search
    (`capped_fts`, `capped_vector_search`), and the indexes are removed along
    with the data they cover.
