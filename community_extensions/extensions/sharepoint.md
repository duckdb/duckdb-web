  extended_description: |
    Registers a `sharepoint://` filesystem backed by Microsoft Graph, so any
    DuckDB path expression can address a file in a SharePoint document library
    or OneDrive with no download step. Because DuckDB dispatches file access
    through its virtual filesystem, `read_parquet`, `read_csv`, `COPY`, `glob`
    and DuckLake all inherit the scheme.

    Unlike Google Drive, Graph addresses items by path, so there is no
    path-resolution cache and no duplicate-name ambiguity. Reads are ranged
    and served from a block cache. Writes stream through a Graph upload session
    in bounded memory and the file appears when it is closed (Graph cannot
    write at a byte offset, so positional writes raise rather than corrupt).
    Besides app-only client credentials, a user can sign in with
    `device_code` or `authorization_code`. Also registers the
    scheme-generic `write_blob`, `remove_file`, `move_file` and `file_size` SQL
    functions, which work for any filesystem DuckDB can reach.

    This is **SharePoint / OneDrive via Microsoft Graph**, not Azure Blob
    Storage — a different product with a different API. For `az://`/`abfss://`
    containers use the `azure` extension.
