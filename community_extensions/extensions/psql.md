  extended_description: |
    PSQL extends DuckDB's SQL with a pipe syntax to provide simple composable queries. It's a lightweight variant of piped languages such as [PRQL](https://prql-lang.org) and [Kusto](https://docs.microsoft.com/azure/data-explorer/kusto/query/samples?pivots=azuredataexplorer), yet leveraging the full power of DuckDB's SQL.

    Every stage continues a `FROM`-first query on the result of the previous stage: `A |> B` is `FROM (A) B`. A stage can therefore contain anything that can follow the first table of a `FROM`-first query, such as joins, `SELECT`, `WHERE`, `GROUP BY` or `ORDER BY`, as well as an alias for that table, which needs `AS`, as in `|> as invoices` above.

    Pipelines can be used anywhere a query can appear: in subqueries, CTEs, views, `CREATE TABLE ... AS`, `INSERT INTO ...`, and so on. A final `|> to 'file'` stage (or `|> copy to 'file'`) writes the result of a pipeline to a file, a short-hand for `COPY (pipeline) TO 'file'`.

    PSQL also supports the operators of [BigQuery's pipe syntax](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/pipe-syntax) that map directly to DuckDB's `SELECT`:

    - `|> extend expr [as alias], ...` is `|> select *, expr [as alias], ...`
    - `|> set column = expr, ...` is `|> select * replace (expr as column, ...)`
    - `|> drop column, ...` is `|> select * exclude (column, ...)`
    - `|> rename column [as] new_name, ...` is `|> select * rename (column as new_name, ...)`
    - `|> distinct` is `|> select distinct *`

    ```sql
    from 'https://raw.githubusercontent.com/ywelsch/duckdb-psql/main/example/invoices.csv' |>
    drop billing_address, billing_state, billing_postal_code |>
    rename billing_city as city, billing_country as country |>
    set invoice_date = invoice_date::date |>
    extend round(total * 0.8, 2) as income |>
    limit 3;
    ```

    PSQL requires DuckDB 2.0 or later, whose parser is extensible. The pipe syntax is a grammar extension, which loading PSQL activates on every connection. A connection can opt out with `reset active_grammar_extensions;`, and opt in again with `call psql_enable();`.

    See the [README](https://github.com/ywelsch/duckdb-psql) for more examples, and for the BigQuery operators that PSQL leaves out because DuckDB's SQL doesn't need them.
