  extended_description: |
    Reads and writes ORCID v3.0 XML and JSON. Turns ORCID documents into
    relational tables, and rows back into ORCID documents, for research-information, library, bibliometrics and CV workflows. It
    reads Public API responses, saved records, and the yearly ORCID
    Public Data File dumps (`.tar` / `.tar.gz`, streamed member by member, also
    over https), in either format (told per file). The XML reader, the JSON
    parser, the writers, the ISO 7064 check and SHA-256 are small
    dependency-free C++ written from the specifications: no libxml2, no JSON
    library, no OpenSSL, no vcpkg. A pure crosswalk, for any user and any
    purpose: no network calls, no policy (consent, access and rate limits
    belong to applications).

    ### Not affiliated with ORCID
    yorc-duckdb is an independent open-source project. It is not affiliated
    with, endorsed by or sponsored by ORCID, Inc. It does not provide access
    to the ORCID Sandbox or the ORCID Member API, and makes no requests to
    ORCID: it reads ORCID documents and Public Data File archives you already
    have.

    ### Record tables
    `orcid_works`, `orcid_fundings`, `orcid_affiliations` (all seven types:
    employment, education, qualification, invited position, distinction,
    membership, service), `orcid_peer_reviews`, `orcid_research_resources`,
    `orcid_research_resource_items`, `orcid_research_resource_hosts`,
    `orcid_contributors`,
    `orcid_external_ids`, `orcid_person`, `orcid_person_items` (other names,
    URLs, emails, addresses, keywords, person ids) and `orcid_history`. Each
    reads a full `/record`, a section collection, a single item or a `bulk`
    response.

    ### Other API messages
    `orcid_summary` and `orcid_summary_items` (the record summary endpoint:
    per-type counts, email domains, listed ids, employments and activities),
    `orcid_search_results` (search and expanded search), `orcid_errors`
    (error responses, including the per-entry errors of bulk responses),
    `orcid_notifications` (permission and custom inbox notifications) and
    `orcid_group_ids` (peer-review group ids).

    ### History of a record
    `orcid_timeline` lists the dated creation and last modification of every
    item in one snapshot. `orcid_changes(old, new)` compares two snapshots (for
    example the same iD in two yearly Public Data File releases) and reports
    added, removed and modified items, one row per changed field.
    `orcid_documents(path)` lists the raw documents of files and archive
    members (with the iD from the path), so two releases can be paired by
    record and compared without unpacking them.
    `orcid_dump_sample(archive, n, seed)` draws a reproducible sample of the
    records of a dump, the same picks as the yorc-rs and yorc-zig libraries.

    ### Writing: ORCID XML and JSON documents
    `orcid_work_to_xml` / `orcid_work_to_json` and the same for fundings,
    affiliations (all seven types), peer reviews, research resources, person
    items (addresses, keywords, other names, researcher URLs, external
    identifiers) and group ids take a STRUCT of the reader's columns (with
    lists of external ids, contributors and resource items) and return the
    document, valid against ORCID's XSDs, in ORCID's element order and JSON
    conventions. `orcid_bulk_works_to_xml` / `_json` build bulk documents of
    up to 100 works. Read, write and read again give the same rows. The
    documents are returned as strings; nothing is sent to ORCID.

    ### Three forms of every table, and scalars
    Each table function `orcid_<section>(path)` reads XML or JSON files, globs
    and URLs through DuckDB's file system (named parameters `members`,
    `max_records` and `json_root`), and has `orcid_<section>_xml(xml)` and
    `orcid_<section>_json(json)` twins for documents held in a column (lateral
    joins); likewise `orcid_changes_xml` and `orcid_changes_json`. Every
    record-table row carries the record iD and a SHA-256 of its source
    document. Files and archive members are scanned in parallel, in document
    order, with progress reporting.
    `orcid_valid` and `orcid_normalize` check and canonicalise iDs (ISO 7064
    MOD 11-2; URL prefixes, missing hyphens and a lowercase check digit are
    accepted). On DuckDB v2.0 the file readers are multi-file readers (lists of
    paths, `filename` and `file_index` columns, `union_by_name`,
    `hive_partitioning`, parallel across files).
