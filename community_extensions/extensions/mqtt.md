    ## mqtt — MQTT Message Ingestion for DuckDB

    A native Rust DuckDB loadable extension that subscribes to any
    [MQTT](https://mqtt.org) broker and returns the received messages as SQL
    rows — powered by pure-Rust [rumqttc](https://github.com/bytebeamio/rumqttc)
    (MQTT 3.1.1/5), written against DuckDB's C Extension API (ABI v1.2.0)
    through [quack-rs](https://github.com/tomtom215/quack-rs). No native broker
    library, no Python, no background services.

    Each `mqtt_scan` call is a bounded one-shot subscription: connect →
    subscribe → collect → disconnect. It fits DuckDB's table-function pull
    model — no threads outlive the query.

    ### Functions

    | Function | Description |
    |---|---|
    | `mqtt_scan(url, topic, max_messages, timeout_secs)` | Subscribe to `topic` on `url`, collect up to `max_messages` within `timeout_secs` → table |
    | `mqtt_version()` | Build/engine info string |

    `mqtt_scan` columns: `received_at TIMESTAMP, topic VARCHAR, qos TINYINT,
    retain BOOLEAN, payload VARCHAR (lossy UTF-8), payload_bytes BLOB (lossless)`.

    Arguments are bind-time constants (literals). `url` accepts `host`,
    `host:port`, `mqtt://…`, `mqtts://…` (default ports 1883/8883). `topic`
    supports MQTT wildcards (`+` single level, `#` multi-level). The scan
    stops at `max_messages` or `timeout_secs`, whichever hits first.
    Retained messages matching the filter are delivered on subscribe, which
    makes deterministic one-shot tests easy. Connection failures yield zero
    rows, never an abort.

    ```sql
    -- Per-topic message rates straight from the broker
    SELECT topic, count(*) AS n, avg(length(payload)) AS avg_len
    FROM mqtt_scan('localhost', '#', 1000, 60)
    GROUP BY topic ORDER BY n DESC;

    -- Raw bytes for binary payloads (protobufs, CBOR, …)
    SELECT topic, payload_bytes FROM mqtt_scan('localhost', 'telemetry/#', 10, 5);
    ```

    Long-running streaming ingest is out of scope for v1; the recommended
    pattern is periodic incremental scans keyed on `received_at`.

    Windows and musl builds are excluded pending CI coverage, matching the
    other quack-rs based community extensions.

    →  [GitHub](https://github.com/alitrack/duckdb_mqtt)
