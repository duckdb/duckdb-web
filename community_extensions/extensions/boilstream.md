    BoilStream 0.9.0 is a breaking client protocol release for DuckDB 2.0.
    It requires a compatible BoilStream server and an independently provisioned
    installation public key on every DuckDB connection. Older client/server
    protocol combinations are unsupported; there is no legacy fallback.

    A pinned Noise channel authenticates the server before passwords, bootstrap
    tokens or OPAQUE messages are sent. Authentication and remote-secret requests,
    replies, status and session metadata use authenticated encrypted bodies, so
    security does not depend on browser access to HTTP response headers or TLS
    confidentiality. HTTPS remains the deployment policy. This does not encrypt
    all Quack query traffic or protect a compromised embedding process.

    Registration, MFA, bootstrap login, remote secret storage, explicit session
    renewal and managed catalog discovery are available. Credentials remain in
    connection memory; logout, replacement and teardown retire that connection's
    authority. Restart requires login again. Server hosting is separate from this
    public client extension.

    Actual native, WASM EH and pthread clients pass the private-server protocol
    gate over plaintext loopback with response security headers removed. Public
    CI covers native security, Rust dependency audits, both browser variants and
    the distribution matrix. MVP WASM is excluded.

    Threaded Quack needs the paired source-built shared-memory artifact; the
    currently pinned public Quack artifact is incompatible with the threaded
    runtime. Load dynamic extensions before enabling query workers. Native HTTP
    uses httpfs; managed attachment requires the compatible quack extension.
