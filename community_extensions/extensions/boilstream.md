    BoilStream provides remote secret storage with OPAQUE password authentication,
    email/password registration, MFA login, and bootstrap-token authentication.
    It supports per-connection session state, signed requests, encrypted responses,
    and managed catalog discovery with explicit attachment.

    Version 0.8.2 hardens URL validation and credential cleanup and qualifies a
    pinned DuckDB 2.0 WASM baseline. Native macOS/Linux ARM64 and browser EH Quack
    integration were tested. Threaded Quack compatibility passes with the pinned,
    source-built shared-memory artifact included in the regression workflow's
    downloads. DuckDB's public threaded Quack artifact is still incompatible;
    browser deployments must serve the compatible paired artifact as described
    in the compatibility guide. Load threaded extensions before enabling query
    workers. MVP WASM is excluded.

    Remote operations require a compatible BoilStream server and HTTPS (HTTP is
    allowed only for exact loopback hosts). Native HTTP uses httpfs; managed Quack
    attachment requires the core quack extension. Authentication does not provide
    blanket protection against compromised TLS endpoints or embedding processes.

    The upstream OPAQUE dependency upgrade resolves the production Rust audit
    advisory and is tested against existing OPAQUE 3 password records. Host-library
    findings and full browser server-authentication coverage remain separate.
    See the [compatibility and deployment guide](https://github.com/dforsber/boilstream-extension/blob/94e2885365525a56320cac04c1661c244ee935ff/test/wasm/QUACK_COMPATIBILITY.md)
